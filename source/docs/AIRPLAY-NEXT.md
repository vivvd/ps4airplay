# Перенос AirPlay после проверки PS4

Не начинать с рекламы неработающего приёмника в сети. Сначала подтвердить
VideoOut/AudioOut и сетевой сервер на целевой 13.52. Эта диагностическая сборка
не изменяет HEN и не добавляет новый kernel exploit.

## Музыка — первый полноценный сценарий

Проверить ядро UxPlay на конкретной версии iOS с Apple Music, затем переносить
его на PS4. Критерий: устройство видно в AirPlay, музыка слышна, громкость
регулируется с iPhone, после отключения можно подключиться снова. Записывать
название источника и фактическую версию iOS для каждого результата.

Точки интеграции закреплённого UxPlay:

- `lib/raop.h`: жизненный цикл raop_init/raop_init2/start_httpd/destroy;
  callbacks audio_process, audio_get_format, audio_set_volume, audio_flush,
  audio_set_metadata, audio_set_coverart и conn_reset.
- `lib/stream.h`: формат входных аудио/видеопакетов; данные в callback не
  считать долгоживущими — владение и копирование проверить по реализации.
- `lib/crypto.c`, `pairing.c`, `srp.c`: libcrypto. Нужна целевая сборка с
  рабочим источником энтропии PS4. Не подменять генератор случайных чисел.
- `lib/raop_handlers.h`: libplist, обработка параметров сессии.
- `lib/dnssd.c`, `lib/mdnsd`: регистрация mDNS. Встроенная реализация на
  текущей ветке экспериментальная, проверить multicast sockets на PS4.
- `lib/threads.h`, `sockets.h`, `compat.c`, `netutils.c`: проверить совместимость
  с OpenOrbis musl и Orbis, а не делать вывод только из родства с FreeBSD.

Callbacks дают кодированные данные. Нужны аудиодекодеры для реально
согласованных форматов (например AAC/ALAC), преобразование частоты при
необходимости, PCM FIFO и AudioOut. Сам приём пакетов ещё не означает звук.

Не переносить GStreamer целиком. Сначала выделить библиотеку протокола без
desktop main-loop и renderer. Собрать libcrypto/libplist под PS4, затем
протокол с выводом диагностических событий, затем адаптер PCM.

## Видео

1. Зафиксировать корректные структуры и ABI H.264-декодера из проверенного
   открытого проекта. Проверка наличия export в 0.01 этого не делает.
2. Прогнать локальные H.264-векторы с разными размерами/профилями. Сравнить
   декодированные кадры с эталоном; проверить границы выделенной памяти.
3. Подключить video_process/video_set_codec_and_size из UxPlay. Явно
   согласовывать H.264, пока HEVC не поддержан. Начать с 720p30.
4. Синхронизировать по временным меткам; использовать ограниченные очереди,
   восстановление после flush/reset, освобождение ресурсов при TEARDOWN.
5. Проверить поворот, смену приложения и повторное подключение на iPhone.
6. Добавлять прямой YouTube HLS через on_video_play/scrub/rate/stop и
   on_video_acquire_playback_info. Нужен отдельный проверенный HLS-плеер;
   вывод H.264 из mirroring сам по себе прямой HLS не реализует.

Safari: проверять конкретные сайты и оба режима отдельно. Наличие кнопки
AirPlay не гарантирует совместимость стороннего приёмника. DRM-контент и
AirPlay 2 multiroom вне первого выпуска. Mac — вторичный источник после iPhone;
расширенный рабочий стол исключён из scope.

## Критерий первой полезной версии

Apple Music воспроизводит звук через PS4. YouTube и обычное незащищённое видео
Safari работают хотя бы через повтор экрана со звуком. Каждая строка отчёта
должна иметь реальную проверку на устройстве, без подмены host-симуляцией.
